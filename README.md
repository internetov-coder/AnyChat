# AnyChat

AnyChat — Android-приложение на Flutter для общения с LLM через **ваш
собственный API-ключ**. Это «свой ChatGPT»: интерфейс в стиле ChatGPT на
Material 3, 21 провайдер, живой стриминг с рендером Markdown,
мультимодальные вложения и прозрачный контроль контекста диалога.

## Возможности

- **Открывается сразу в чате.** Пустой экран — «С чего начнем?» и композер:
  отправка текста сама создаёт первый чат.
- **Drawer как в ChatGPT**: гамбургер → недавние чаты (меню чата:
  переименовать / сжать историю / системный промпт / удалить), внизу
  pill «Новый чат» и шестерёнка **Настройки**.
- **Ответы модели — Markdown** (заголовки, списки, цитаты, код-блоки) прямо
  на фоне, как в ChatGPT; свои сообщения — в пузыре. У каждого сообщения
  есть кнопка **копирования**.
- **Композер-капсула**: «+» (вложения, включены только если модель их
  принимает), поле ввода, круглая кнопка отправки / стоп во время
  генерации.
- **21 провайдер**: OpenAI-совместимые, Anthropic, Gemini, Vercel AI
  Gateway и локальный Ollama. Ключи — в системном Keystore, маска в UI,
  Base URL override, проверка ключа с локализованной причиной ошибки.
- **Модели**: каталог `/models` с поиском, ценой за 1M токенов, размером
  контекста и бейджами мультимодальности; любой ID можно ввести вручную.
- **Чат**: SSE-стриминг по токенам, Стоп, Перегенерировать, авто-название
  из первого сообщения.
- **Ветвление**: редактирование сообщения создаёт ветку, откат к любому
  сообщению («Ветка отсюда»), переключение веток, старые ветки сохраняются.
- **Контекст**: полоска использованных/лимит токенов (зелёный < 60%,
  жёлтый 60–85%, красный > 85%), «приблизительно» когда лимит неизвестен.
- **Handoff**: «Сжать историю» делает резюме диалога и открывает новый
  чат с ним как системным промптом; старый чат остаётся в истории.
- **Настройки генерации**: temperature, top_p, max_tokens, таймаут,
  системный промпт (глобальный и по-чатовый), плюс расширенные параметры
  (см. ниже): frequency_penalty, top_k, reasoning_effort, лимит контекста,
  глубина истории.
- **Статистика контекста**: тонкая полоска сверху (`12.4K / 128K`, 3px)
  и **круг над композером** — по нажатию показывает занятый и свободный
  контекст, кумулятивные инпут / аутпут / тхинкинг в K. Счётчики берутся
  из usage, который провайдер присылает в стриме (Gemini `usageMetadata`,
  Anthropic `usage`, OpenAI `usage`), иначе оцениваются эвристикой.
- **Акцентный цвет**: Настройки → «Внешний вид» — системный (dynamic
  color) либо чёрный / синий / голубой / зелёный / розовый / красный /
  оранжевый / фиолетовый. Кнопка отправки — `primary`+`onPrimary` (иконка
  всегда читается), во время генерации — красная кнопка стопа.
- **Локализация** ru / en / uk (автоопределение + ручной выбор); все ошибки
  провайдеров переведены и показываются понятным текстом, сырые ответы API —
  только в отладочном логе.

## Установка

Каждый push **с изменениями кода** в `main` публикует **GitHub Release**
с тегом `rN` и ассетом `AnyChat-arm64-rN.apk` (правка одной документации
CI не запускает — фильтр `paths-ignore`):

1. Откройте страницу **Releases** репозитория → последний релиз `rN`.
2. Скачайте ассет `AnyChat-arm64-rN.apk`.
3. Установите на устройство (разрешите установку из неизвестных источников).

Альтернатива — артефакт сборки: **Actions** → последний успешный прогон →
**Artifacts** → `AnyChat-<короткий sha>` (в ZIP лежит `app-release.apk`).

Требования: Android 7.0+ (minSdk 24), интернет или локальный Ollama.

> Release-сборка подписана debug-keystore Flutter (keystore/`.jks` в
> репозитории сознательно нет). Для Play Store подпишите своим ключом.

## Настройка провайдера

1. **Гамбургер → Настройки → «Провайдер и ключ»** — выберите провайдера.
2. Введите **API-ключ** → **Сохранить ключ**. В UI видна только маска
   `sk-...abcd`; ключ хранится в `flutter_secure_storage` (Keystore
   Android) и не попадает ни в БД, ни в лог.
3. При необходимости укажите **Base URL override** (селф-хостинг, прокси,
   Ollama `http://10.0.2.2:11434/v1` для эмулятора). Пустое поле = адрес
   по умолчанию.
4. **Проверить ключ** — минимальный chat-проба (та же модель и формат,
   что в чате, `max_tokens: 32`, таймаут 60 с): ✅/❌ плюс локализованная
   причина при провале.
5. **Настройки → «Модели»** — выбор модели: поиск, цена за 1M токенов,
   контекст, бейджи мультимодальности, либо свой ID в поле «Своя модель».
6. **Настройки → «Генерация» / «Расширенные параметры»** — при желании
   настройте sampling и ограничения (см. ниже). Всё это применяется ко
   всем новым запросам.

Дальше — гамбургер → нужный чат или «Новый чат» и просто пишите.

## Расширенные параметры модели

Раздел **Настройки → «Расширенные параметры»** (отправляются только теми
форматами, которые их понимают):

| Параметр           | Форматы            | Назначение |
|--------------------|--------------------|------------|
| `top_p`            | все                | nucleus sampling, 0–1 (по умолчанию 1.0) |
| `frequency_penalty`| `openai`           | штраф за повторы, −2…2 (по умолчанию 0.0) |
| `top_k`            | `gemini`           | число кандидатов 1–100, выключено по умолчанию |
| `reasoning_effort` | `openai`           | low / medium / high для reasoning-моделей, по умолчанию «Не отправлять» (иначе обычные модели получат 400) |
| Лимит контекста    | —                  | вручную заданный лимит токенов для полоски контекста (пусто = метаданные модели или 128k) |
| Глубина истории    | —                  | отправлять только последние N сообщений (пусто = вся история) |

Температура, `max_tokens`, таймаут и системный промпт живут в разделе
«Генерация» и применяются ко всем трём форматам (температура для
Anthropic автоматически ограничивается диапазоном 0…1).

## Вложения (мультимодальность)

| Медиа  | Форматы файлов            | Лимит |
|--------|---------------------------|-------|
| Фото   | jpg, jpeg, png, webp, gif | 20 МБ на файл |
| Видео  | mp4, mov, webm            | 20 МБ на файл |
| Аудио  | mp3, wav                  | 20 МБ на файл |

- Скрепка в композере выключена, если модель не принимает медиа вообще;
  фильтр файлового пикера ограничен форматами, которые поддерживает
  конкретная модель.
- Возможности модели берутся из каталога провайдера (`modalities.input` у
  Vercel, `architecture.input_modalities` у OpenRouter) и дополняются
  эвристикой по ID (`gpt-4o`/`claude`/`gemini` → фото, `gemini` → ещё
  видео и аудио); без данных модель считается текстовой.
- Отправка по формату: OpenAI — `image_url`/`input_audio`/`video_url`
  (data-URI), Anthropic — `image` (base64), Gemini — `inlineData`.
- Вложения хранятся base64 в строке сообщения (schema v2, миграция
  добавляет колонку), копируются при ветвлении; превью фото кэшируется,
  чтобы стрим не декодировал картинку на каждый токен.

## Design decisions

Решения, принятые автономно (и почему):

1. **Версии зафиксированы.** CI использует стабильный Flutter **3.47.8**
   (Dart 3.13.7); `pubspec.yaml` — совместимые версии пакетов (Riverpod 3.x
   + `riverpod_annotation` 4.x, drift 2.35, dio 5.11, `file_picker` 13,
   `flutter_markdown` 0.7).
2. **Без `flutter create`.** Каталог `android/` написан вручную по шаблону
   Flutter 3.47 (Kotlin DSL, AGP 9.1.0, Kotlin 2.4.0, Gradle 9.3.1);
   gradle-wrapper не коммитится — Flutter докачивает его сам.
3. **Без бинарников.** Иконка — векторный `drawable/ic_launcher.xml`;
   в репозитории нет keystore, `.env` и ключей.
4. **Ключи и конфиг разделены.** API-ключи только в
   `flutter_secure_storage`; drift хранит `providers_config` (Base URL),
   чаты, ветки и сообщения (включая base64-вложения).
5. **Доменные модели отделены от drift-строк.** `riverpod_generator` не
   может разрешать типы из `db.g.dart` (part-файл) — генерация падала с
   `InvalidTypeException`. `Chat/Message/Branch` — обычные неизменяемые
   классы с `fromRow`-маппингом в репозиториях; в CI кодогенерация
   подстрахована bootstrap-шагом `build_runner` только для `db.g.dart`.
6. **`drift_flutter` вместо `sqlite3_flutter_libs`** — рекомендация
   документации drift: `driftDatabase(name:)` сам настраивает путь и
   нативные библиотеки.
7. **Собственный SSE-парсер** вместо `flutter_client_sse`: ~100 строк,
   покрыты тестами на чанки, разрезанные посреди слова.
8. **Эвристика токенов** (латиница /4, кириллица /2, +4 на сообщение) —
   без тяжёлых токенизаторов; лимит контекста из метаданных модели,
   иначе 128k «приблизительно».
9. **Riverpod наполовину вручную**: `@riverpod` (codegen) для нотифаеров и
   стрим-провайдеров, обычные `Provider` для синглтонов (БД, репозитории).
10. **Ошибки**: один `ApiErrorType` на три формата, локализация через ARB
    (en/ru/uk); пользователь видит понятную причину, сырые тела ответов —
    только в кольцевом debug-логе (последние 50, экран в настройках).
11. **Ветвление через копирование** сообщений в транзакции drift — проще
    и надёжнее переиспользования `parentId`.
12. **Проверка ключа — chat-проба, а не `/models`:** каталог Vercel AI
    Gateway публичный (отвечает без ключа) и не доказал бы валидности
    ключа. Проба использует ту же модель/формат, что чат, и при провале
    показывает локализованную причину.
13. **Ссылки проверяются на живом API.** Vercel AI Gateway
    (`GET /v1/models` публичен, `POST /v1/chat/completions` → 401 без
    ключа) и Xiaomi MiMo (`/v1/models` и `/v1/chat/completions` отвечают
    401 «Invalid API Key») проверены запросами к продовым хостам; цены
    `pricing.input/output` (Vercel) парсятся наравне с `prompt/completion`
    (OpenRouter).
14. **Визуал в стиле ChatGPT на Material 3.** Приложение открывается в
    чате; вместо `AppBar` — круглые плавающие кнопки (гамбургер-глиф из
    `CustomPainter`, «новый чат»), пустой экран — «С чего начнем?» с
    композером, создающим чат при отправке. Ответы модели — голый Markdown
    на фоне (как в GPT), свои — пузырь `primaryContainer`; у сообщений
    кнопка копирования (`Clipboard`), во время стрима — курсор `▌`.
    Композер вынесен в `ChatComposer` (общий для чата и пустого экрана).
    Drawer непрозрачный (`Drawer` со своим фоном): заголовок, чаты с меню,
    внизу pill «Новый чат» и шестерёнка настроек. Нижней `NavigationBar`
    и отдельного списка чатов нет; переходы — обычный `Navigator`.
15. **`gen-l10n` с `nullable-getter: false`**: `AppLocalizations.of`
    не-nullable; сгенерированные файлы не коммитятся, создаются в CI до
    `flutter analyze`.
16. **cleartext HTTP разрешён** (`usesCleartextTraffic="true"`) — нужен
    для локального Ollama по `http://`.
17. **Релизы автоматические**: push с кодом в `main` создаёт Release
    `rN` (N = максимум существующих + 1) с ассетом
    `AnyChat-arm64-rN.apk`; документационные push и PR не запускают CI
    (`paths-ignore`), `[skip ci]` тоже работает.
18. **Мультимодальность по возможностям модели** — гейт скрепки по
    `ModelModality`, `file_picker` (SAF, без разрешений), base64 в строке
    сообщения; миграции схемы v1 → v2 (вложения) и v2 → v3 (счётчики
    usage) (детали в разделе «Вложения»).
19. **Расширенные параметры — только туда, где их понимают.** `top_p`
    уходит всем форматам, `frequency_penalty` — только `openai`,
    `top_k` — только `gemini` (иначе провайдер отклонит запрос);
    лимит контекста и глубина истории — чисто клиентские: срез последних N
    сообщений делается перед отправкой, лимит влияет только на полоску
    контекста.

20. **Usage-счётчики без риска для запроса.** Провайдеру НЕ отправляются
    доп. флаги ради статистики (никаких `stream_options` — это сломало бы
    строгие совместимые API): usage читается из того, что провайдер сам
    присылает в потоке (Gemini `usageMetadata` c `thoughtsTokenCount`,
    Anthropic `usage` в `message_start`/`message_delta`, OpenAI `usage`).
    Если провайдер молчит — вход/выход оцениваются эвристикой токенов.
    Кумулятивные счётчики хранятся в чате (schema v3) и показываются по
    кругу над композером.
21. **Акцент и кнопки композера.** Акцентный цвет — обычная смена seed для
    `ColorScheme.fromSeed` (явный выбор сильнее dynamic color); круглая
    кнопка отправки использует пару `primary/onPrimary`, стоп —
    `error/onError`: гарантированный контраст на любой теме. Раньше
    `IconButton.filled` давал невнятный контраст на ярком `primaryContainer`.

## Ограничения v1

- Только Android (iOS / web / desktop не поддерживаются).
- Нет tool calling / функций и генерации изображений; вложений — только
  готовые файлы (записи с микрофона нет), `video_url` для
  OpenAI-совместимых провайдеров — best-effort (не все провайдеры видео
  принимают).
- Нет экспорта/импорта чатов, поиска по истории и пагинации — чат целиком
  грузится в память.
- Лог ошибок хранится только в памяти процесса.
- Индикатор контекста — эвристика без токенизатора; значения
  «приблизительно», когда лимит модели неизвестен.
- `reasoning_effort` уходит только в openai-совместимые API и только когда
  включён вручную — для моделей без поддержки провайдер ответит ошибкой;
  thinking-токены видны только если провайдер их присылает в строме.
- Fork ветки копирует сообщения — на экстремально длинных историях это
  заметная задержка.

## Разработка

**Политика CI:** `flutter analyze` — **0 issues** (error / warning / info
валят прогон), `flutter test` — зелёный, `flutter build apk --release` —
собирается; артефакт `AnyChat-<sha>` + релиз `rN`.

Этапы workflow (`.github/workflows/build.yml`):

```bash
flutter pub get
flutter gen-l10n
dart run build_runner build --build-filter=lib/core/storage/db.g.dart  # bootstrap
dart run build_runner build                                           # полная генерация
flutter analyze
flutter test
flutter build apk --release
# + загрузка ассета и публикация GitHub Release rN
```

Bootstrap-шаг нужен из-за `part 'db.g.dart'`: пока файла нет,
`riverpod_generator` не видит сгенерированные row-типы. Push, где тронуты
только `**/*.md`, `LICENSE` или `.gitignore`, workflow не запускает
(`paths-ignore`).

**Тесты** (`flutter test`, только логика, без UI): маппинг ошибок
(`api_error_test`), SSE-парсер (`sse_parser_test`), эвристика токенов
(`token_estimator_test`), адаптеры — URL/заголовки/тела трёх форматов,
парсинг `/models` (цены, контекст, модальности), сериализация
`top_p`/`frequency_penalty`/`top_k`, разбор SSE и стрим через мок-dio,
мультимодальные content-parts (`adapters_test`), реестр провайдеров и
эвристика модальностей (`provider_registry_test`), заголовки чатов и
вложения (`chat_models_test`).

Структура:

```
lib/
  main.dart, app.dart           # точка входа, темы, локализация, dynamic color
  core/
    errors/                     # ApiErrorType, локализация, debug-лог
    network/                    # SSE-парсер, dio-клиент, ApiFormat
    storage/                    # drift (schema v2), secure storage, токены
  features/
    chat/                       # data, domain (Chat/Message/Branch/вложения),
                                # state (сессия, текущий чат), presentation
    home/                       # shell: drawer и пустой экран
```
