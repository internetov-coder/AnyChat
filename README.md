# AnyChat

> Android-приложение (Flutter) для общения с LLM через **ваш API-ключ**.
> Свой ChatGPT на Material 3: свои провайдеры под любой эндпоинт, SSE-стриминг,
> Markdown-ответы, ветвление диалога, контроль контекста, вложения (фото / видео /
> аудио — по возможностям модели), локализация ru / en / uk.

## Установка

Проект в стадии **alpha**: каждый push с кодом в `main` публикует релиз
`alpha-N` с ассетом `AnyChat-arm64-alpha-N.apk`.

1. Откройте **Releases** → свежий `alpha-N`.
2. Скачайте `AnyChat-arm64-alpha-N.apk` и установите (разрешите установку
   из неизвестных источников).

Требования: Android 7.0+ (minSdk 24), интернет или локальный Ollama.

> Подпись стабильна с alpha-1 (debug-keystore кешируется в CI). Если
> обновление поверх старой сборки падает с конфликтом подписи — установите
> alpha-1+ один раз «с нуля», дальше всё встанет поверх.

## Быстрый старт

1. **Гамбургер → Настройки → Провайдер → «+»**: название, эндпоинт
   (например `https://api.openai.com/v1`), формат (`openai` у большинства
   шлюзов; `anthropic`/`gemini` — нативные API) и API-ключ. Ключ хранится в
   Keystore, в UI видна только маска `sk-...abcd`.
2. В меню провайдера — **Проверить ключ**: минимальный chat-проба
   (`max_tokens: 32`); при ошибке показывается её локализованная причина.
3. **Настройки → Модели**: выбор модели (поиск, цена за 1M токенов, контекст,
   бейджи мультимодальности) либо ввод своего ID в поле «Своя модель».
4. Пишите в чат. Drawer: переименование чата, его системный промпт,
   **Сжать историю**, удаление, внизу — «Новый чат» и Настройки.
   Ветвление: правка сообщения создаёт ветку, «Ветка отсюда» — откат.

## Параметры и вложения

| Где | Параметр | Что делает |
|-----|----------|------------|
| Генерация | `max_tokens`, таймаут, системный промпт | базовые ограничения запроса; системный промпт есть и глобальный, и по-чатовый |
| Расширенные | `frequency_penalty` (−2…2) | штраф за повторы — только для openai-совместимых |
| Расширенные | `top_k` (1–100) | число кандидатов — только для gemini |
| Расширенные | `reasoning_effort` | уровни приходят **из каталога API** выбранной модели; по умолчанию «Не отправлять» |
| Расширенные | лимит контекста, глубина истории | клиентские: индикатор контекста и срез последних N сообщений перед отправкой |

Temperature и `top_p` не отправляются вообще — работают дефолты провайдера.

**Вложения** — скрепка в композере включена, только если модель принимает медиа
(иначе подсказка «модель не поддерживает вложения»):

| Медиа  | Форматы файлов            | Лимит |
|--------|---------------------------|-------|
| Фото   | jpg, jpeg, png, webp, gif | 20 МБ |
| Видео  | mp4, mov, webm            | 20 МБ |
| Аудио  | mp3, wav                  | 20 МБ |

Как отправляются: openai → `image_url` / `input_audio` / `video_url`
(data-URI), anthropic → `image` (base64), gemini → `inlineData`.
Возможности модели берутся из каталога (`modalities.input`,
`architecture.input_modalities`) и дополняются эвристикой по ID; без данных
модель считается текстовой. Вложения лежат base64 в строке сообщения
(schema v2) и переживают ветвление.

## Design decisions (только важное)

1. **Версии зафиксированы**: Flutter 3.47.8 / Dart 3.13.7 и пакеты под них
   (Riverpod 3 + codegen 4, drift 2.35, dio 5.11, file_picker 13).
2. **Только пользовательские провайдеры**: жёсткий реестр удалён — таблица
   `providers_config` (название / эндпоинт / формат) и экран с кнопкой «+».
   Существующие установки мигрируются (schema v4): старые id сохраняются
   вместе с ключами, Base URL и название заполняются из прежнего реестра
   (legacy-карта живёт только в миграции).
3. **Доменные модели отделены от drift-строк.** `riverpod_generator` не
   может разрешить типы из `db.g.dart` (это part-файл) — генерация падала
   с `InvalidTypeException`. Поэтому `Chat/Message/Branch` — рукописные
   классы с `fromRow`-маппингом; в CI `db.g.dart` создаётся bootstrap-шагом
   до полного `build_runner`.
4. **Ключи и проверка.** Только `flutter_secure_storage` + маска в UI;
   проверка — chat-проба (модель из настроек или первая из каталога,
   `max_tokens: 32`), а не `/models`: публичные каталоги (Vercel отвечает
   и без ключа) не доказали бы валидности ключа. При провале показывается
   локализованная причина, сырой ответ — в debug-логе.
5. **Визуал ChatGPT на Material 3.** Без AppBar: круглые плавающие кнопки
   (гамбургер-глиф, «новый чат»); пустой экран «С чего начнем?» → композер
   сам создаёт чат; drawer непрозрачный — чаты сверху, «Новый чат» и
   Настройки снизу. Ответы — голый Markdown на фоне, у каждого сообщения
   кнопка копирования, текст выделяется через `SelectionArea`, ссылки
   открываются снаружи (`url_launcher`), код-блоки рисует собственный
   `pre`-билдер: вырезает заборы из трёх обратных кавычек, попавшие внутрь блока, и переносит
   длинные строки. Подсветки синтаксиса нет — `flutter_highlight`/`highlight`
   требуют Dart < 3.
6. **Мультимодальность по возможностям модели**: гейт скрепки, фильтр
   файлового пикера по поддерживаемым форматам, лимит 20 МБ;
   `file_picker` работает через SAF без разрешений.
7. **Ошибки**: один `ApiErrorType` на три формата, сообщения локализованы
   (en/ru/uk), сырые тела ответов — только в кольцевом debug-логе
   (последние 50 записей, экран в настройках).
8. **Usage-счётчики без риска для запроса**: usage читается из того, что
   провайдер сам присылает в стриме (Gemini `usageMetadata`, Anthropic
   `usage`, OpenAI `usage`) — никаких `stream_options`, которые ломают
   строгие совместимые API; иначе оценка эвристикой. Счётчики копятся в
   чате (schema v3) и показываются по кругу: занятый/свободный контекст и
   input / output / thinking в K.
9. **Релизы**: push с кодом в `main` → `alpha-N` (N = максимум существующих
   + 1) с ассетом `AnyChat-arm64-alpha-N.apk`; документация и PR CI не
   запускают (`paths-ignore`, работает и `[skip ci]`); подпись —
   кешированный debug-keystore, поэтому обновления встают поверх.
10. **Схема БД**: v2 — base64-вложения, v3 — счётчики usage, v4 —
    пользовательские провайдеры; миграции применяются автоматически.

## Ограничения (alpha)

- Только Android; нет iOS / web / desktop.
- Нет подсветки синтаксиса кода — код-блоки моноширинные, без цветов
  (пакеты подсветки требуют Dart < 3).
- Нет tool calling и генерации изображений; вложения — только готовые
  файлы (без записи с микрофона), `video_url` — best-effort (не все
  провайдеры видео принимают).
- Нет экспорта чатов и поиска по истории; лог ошибок живёт в памяти.
- Индикатор контекста — эвристика без токенизатора, значения
  «приблизительно», когда лимит модели неизвестен.
- `reasoning_effort` уходит только в openai-совместимые API и только когда
  включён вручную; thinking-токены видны, если провайдер их присылает.
- Fork ветки копирует сообщения — на экстремально длинных историях это
  заметная задержка.

## Разработка

CI: `flutter analyze` — **0 issues** (error / warning / info валяют прогон),
`flutter test` — зелёный, `flutter build apk --release` → артефакт + релиз
`alpha-N`.

```bash
flutter pub get && flutter gen-l10n
dart run build_runner build   # в CI перед этим bootstrap:
                              # dart run build_runner build --build-filter=lib/core/storage/db.g.dart
flutter analyze && flutter test
```

```
lib/
  core/        # ошибки, SSE, токены, drift (schema v4), secure storage
  features/
    chat/      # чат: репозитории, домен, сессия, экран, композер
    home/      # shell: drawer и пустой экран
    providers/ # CRUD своих провайдеров + адаптеры wire-форматов
    models/    # выбор модели
    settings/  # настройки, генерация, внешний вид
  l10n/        # ARB: app_en / app_ru / app_uk
test/          # unit-тесты: ошибки, SSE, токены, адаптеры, провайдеры
```
