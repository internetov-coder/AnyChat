# AnyChat

AnyChat — Android-приложение на Flutter для общения с LLM через **ваш собственный API-ключ**.
Аналог «своего ChatGPT» с фокусом на прозрачный контроль контекста и минималистичный Material 3 UI:
21 провайдер, стриминг SSE, вложения (фото/видео/аудио — если их принимает
модель), ветвление диалога, индикатор токенов и сжатие истории (handoff).

## Установка

Каждый зелёный push в `main` публикует **GitHub Release** с тегом `rN`
и ассетом `AnyChat-arm64-rN.apk`:

1. Откройте страницу **Releases** репозитория → последний релиз `rN`.
2. Скачайте ассет `AnyChat-arm64-rN.apk`.
3. Установите на устройство (разрешите установку из неизвестных источников).

Альтернатива — артефакт самой сборки: вкладка **Actions** → последний
успешный прогон → **Artifacts** → `AnyChat-<короткий sha>`
(в ZIP лежит `app-release.apk`).

Требования: Android 7.0+ (minSdk 24), internet-соединение или локальный Ollama.

> Подпись release-сборки — debug-keystore Flutter (в репозитории сознательно
> нет keystore/`.jks`). Для Play Store подпишите свой ключом.

## Настройка провайдера

1. **Настройки → Провайдер и ключ → Провайдер** — выберите одного из 21 провайдера.
2. В карточке провайдера введите **API-ключ** и нажмите **Сохранить ключ**.
   В UI показывается только маска вида `sk-...abcd`; сам ключ хранится в
   `flutter_secure_storage` (Keystore Android) и никогда не попадает в БД или лог.
3. (Опционально) укажите **Base URL override** — для селф-хостинга, прокси
   или Ollama (`http://10.0.2.2:11434/v1` для эмулятора, свой адрес — для устройства).
4. Нажмите **Проверить ключ** — AnyChat сделает минимальный chat-проба
   (та же модель и формат, что в чате, `max_tokens: 32`, таймаут 60 с)
   и покажет ✅/❌ вместе с локализованной причиной ошибки.
5. **Настройки → раздел «Модели»** — выберите модель из списка (поиск,
   цена за 1M токенов, размер контекста, бейджи мультимодальности) либо
   введите ID вручную (поле «Своя модель»).
6. Приложение открывается сразу в чате. **Гамбургер** слева сверху открывает
   панель: сверху — недавние чаты (и «Новый чат»), снизу — **Настройки**.
   В чате: стриминг SSE, **Стоп**, **Перегенерировать**, редактирование
   сообщений (создаёт ветку), откат («Ветка отсюда»), переключение веток,
   полоска контекста, **Сжать историю** (handoff) в меню чата и
   **вложения** — скрепка активна, только если выбранная модель принимает
   фото/видео/аудио (иначе она выключена с подсказкой).

## Design decisions

Решения, принятые autonomно (и почему):

1. **Версии зафиксированы.** CI использует стабильный Flutter **3.47.8**
   (Dart 3.13.7); `pubspec.yaml` — актуальные совместимые версии пакетов
   (Riverpod 3.x + `riverpod_annotation` 4.x, drift 2.35, dio 5.11).
2. **Без `flutter create`.** Каталог `android/` написан вручную по шаблону
   `flutter create` для 3.47 (Kotlin DSL, AGP 9.1.0, Kotlin 2.4.0, Gradle 9.3.1,
   флаги `android.newDsl=false` / `android.builtInKotlin=false`). Gradle-wrapper
   (`gradlew`, `gradle-wrapper.jar`) не коммитится — Flutter сам докачивает его
   из кеша SDK при сборке.
3. **Без бинарников.** Иконка приложения — векторный `drawable/ic_launcher.xml`
   вместо PNG-mipmaps; никаких keystore, `.env` и ключей в репозитории.
4. **Ключи и конфиг разделены.** API-ключи — только в
   `flutter_secure_storage`; drift хранит `providers_config` (Base URL),
   чаты, ветки и сообщения.
5. **Доменные модели отделены от drift-строк.** `riverpod_generator` не может
   разрешить типы, сгенерированные в `db.g.dart` (это `part`-файл): генерация
   падала с `InvalidTypeException`. Поэтому `Chat/Message/Branch` — обычные
   неизменяемые классы в `features/chat/domain/models.dart`, а репозитории
   маппят строки через `fromRow`. Плюс: кодогенерация drift и riverpod больше
   не зависит от порядка выполнения (в CI всё равно сначала создаётся
   `db.g.dart`).
6. **`drift_flutter` вместо `sqlite3_flutter_libs`.** Так рекомендует
   документация drift: `driftDatabase(name:)` сам настраивает путь и
   нативные библиотеки.
7. **Собственный SSE-парсер** (`sse_parser.dart`) вместо `flutter_client_sse`:
   ~100 строк, покрыт тестами на разрезанные чанки и не тянет зависимости.
8. **Эвристика токенов.** Латиница /4, кириллица /2, прочие символы — 1/символ,
   +4 на сообщение. Лимит контекста берётся из метаданных модели, иначе 128k
   и пометка «приблизительно».
9. **Riverpod наполовину вручную.** `@riverpod` (codegen) — для нотифаеров и
   стрим-провайдеров; простые синглтоны (БД, репозитории, key-store) — обычные
   `Provider`, чтобы не плодить генерацию без нужды.
10. **Ошибки.** Один `ApiErrorType` на три wire-формата, локализация через ARB
    (en/ru/uk), сырые тела — только в кольцевом debug-логе (последние 50,
    экран «Отладочный лог ошибок» в настройках).
11. **Ветвление через копирование.** Fork ветки копирует её сообщения
    (транзакция drift) — проще и надёжнее переиспользования `parentId`,
    чаты в v1 небольшие.
12. **Проверка ключа — минимальный chat-проба** (модель и формат как в чате,
    `max_tokens: 32`, таймаут 60 с), а не запрос `/models`: у Vercel AI
    Gateway каталог моделей публичный (отвечает и без ключа), поэтому список
    ничего не доказывал бы о валидности ключа. При провале под кнопкой
    показывается локализованная причина (401 / таймаут / недоступная
    модель), сырой ответ уходит в отладочный лог.
13. **Vercel AI Gateway** добавлен как OpenAI-совместимый провайдер
    (`https://ai-gateway.vercel.sh/v1`): базовый URL и публичность
    `GET /models` проверены запросами к живому API, а цены из каталога
    (`pricing.input/output`) парсятся наравне с OpenRouter (`prompt/completion`).
14. **Навигация и визуал в стиле ChatGPT (в рамках MD3):** приложение
    открывается сразу в чате; вместо `AppBar` — круглые плавающие кнопки
    (гамбургер-глиф слева, «новый чат» справа), на пустом экране — большой
    заголовок «С чего начнем?» и композер, который создаёт первый чат при
    отправке. Композер — одна капсула: «+» слева (вложения), поле в центре,
    круглая кнопка отправки справа. `Drawer`: заголовок AnyChat, список
    недавних чатов (пункты меню чата: переименовать/сжать/промпт/удалить),
    внизу pill «Новый чат» и круглая шестерёнка «Настройки» (в ней выбор
    модели). Отдельного экрана-списка чатов и нижней `NavigationBar` нет;
    Base URL показывается только как подсказка-помощь, без ссылки в поле.
    Переходы — обычный `Navigator`, go_router избыточен.
15. **`gen-l10n` c `nullable-getter: false`:** `AppLocalizations.of(context)`
    не-nullable, меньше `!` в UI-коде. Сгенерированные файлы не коммитятся —
    создаются в CI до `flutter analyze`.
16. **cleartext HTTP разрешён** (`android:usesCleartextTraffic="true"`) —
    нужен для локального Ollama по `http://`.
17. **Filled icon button.** В Flutter нет класса `FilledIconButton` — поле
    ввода использует `IconButton.filled` (тот же Material 3 filled icon button
    со скруглением 28dp).
18. **JDK 21 в CI** — Gradle 9.3 / AGP 9.1 требуют 17+, 21 — стабильный LTS.
19. **Релизы автоматические.** Каждый успешный push в `main` создаёт GitHub
    Release с тегом `rN` (N = максимум существующих `rN` + 1), заголовком
    `AnyChat rN` и ассетом `AnyChat-arm64-rN.apk` — схема имени из
    требования плюс стандартное расширение, чтобы Android считал файл APK.
    PR-прогоны релизов не создают; при гонке/повторном запуске workflow
    занимает следующий свободный номер тега.

20. **Мультимодальность по возможностям модели.** Ввод модели
    (`ModelModality`: image/video/audio) читается из каталога провайдера
    (Vercel `modalities.input`, OpenRouter `architecture.input_modalities`)
    и дополняется эвристикой по ID (`gpt-4o`/`claude`/`gemini`/… → фото,
    `gemini` → ещё видео и аудио). Скрепка выключена, если медиа не
    поддерживаются; фильтр `file_picker` (SAF, без разрешений) ограничен
    jpg/png/webp/gif, mp4/mov/webm, mp3/wav, лимит — 20 МБ. Вложения
    хранятся base64 в строке сообщения (schema v2 + миграция `addColumn`)
    и отправляются по формату: OpenAI — `image_url`/`input_audio`/
    `video_url` (data-URI), Anthropic — `image` (base64), Gemini —
    `inlineData`. Превью фото кэшируется, чтобы стрим не декодировал
    картинку заново на каждый токен.

## Ограничения v1

- Только Android (iOS/web/desktop не поддерживаются).
- Нет рендеринга Markdown в ответах (обычный текст), нет копирования блоками.
- Нет tool calling / функций и генерации изображений; вложений — только
  готовые файлы (без записи с микрофона), список допустимых форматов
  зависит от модели и wire-формата провайдера.
- Нет экспорта/импорта чатов, поиска по истории, пагинации — чаты целиком
  грузятся в память.
- Лог ошибок хранится только в памяти процесса.
- Индикатор контекста — эвристика (без токенизатора), значения «приблизительно».
- Fork ветки копирует сообщения — на экстремально длинных историях может
  быть заметной задержкой.
- Иконка приложения упрощённая (вектор), release-сборка подписана debug-ключом.
- Для Xiaomi MiMo базовый URL помечен TODO и требует подтверждения.
- Локализация UI: en/ru/uk; названия провайдеров и моделей не переводятся.

## Разработка

Политика CI: **`flutter analyze` должен давать 0 issues** (любые error /
warning / info валит прогон), `flutter test` — зелёный, `flutter build apk
--release` — собирается и выкладывается как артефакт `AnyChat-<sha>`.

Локально (нужен Flutter SDK) команда для итераций:

```bash
flutter pub get
flutter gen-l10n
dart run build_runner build --delete-conflicting-outputs
flutter analyze
flutter test
```

Структура:

```
lib/
  main.dart, app.dart           # точка входа, темы, локализация
  core/                         # ошибки, SSE, токены, drift, secure storage
  features/
    chat/                       # data (репозитории), domain, presentation
    home/                       # shell: drawer «недавние чаты + настройки»
    providers/                  # реестр 21 провайдера + адаптеры форматов
    models/                     # выбор модели
    settings/                   # настройки + контроллер
  l10n/                         # ARB: app_en / app_ru / app_uk
test/                           # unit-тесты (ошибки, SSE, адаптеры, реестр,
                                # мультимодальность, заголовки чатов)
```
