# AnyChat

AnyChat — Android-приложение на Flutter для общения с LLM через **ваш
собственный API-ключ**. Это «свой ChatGPT»: интерфейс в стиле ChatGPT
(собранный на Material 3), 21 провайдер, живой стриминг ответа,
мультимодальные вложения и прозрачный контроль контекста диалога.

## Возможности

- **Открывается сразу в чате.** Пустой экран — «С чего начнем?» и композер:
  отправка текста сама создаёт первый чат.
- **Drawer как в ChatGPT**: гамбургер слева сверху → заголовок AnyChat,
  недавние чаты (меню чата: переименовать / сжать историю / системный
  промпт / удалить), внизу pill «Новый чат» и шестерёнка «Настройки».
- **Композер-капсула**: «+» (вложения, доступны только если модель их
  принимает), поле ввода, круглая кнопка отправки / стоп во время
  генерации.
- **21 провайдер** (OpenAI-совместимые, Anthropic, Gemini) + Vercel AI
  Gateway; API-ключи в системном Keystore, маска в UI, Base URL override,
  проверка ключа с локализованной причиной ошибки.
- **Модели**: каталог `/models` с поиском, ценой за 1M токенов, размером
  контекста и бейджами мультимодальности; всегда можно ввести ID вручную.
- **Чат**: SSE-стриминг по токенам, Стоп, Перегенерировать, авто-название
  из первого сообщения.
- **Ветвление**: редактирование сообщения создаёт ветку, откат к любому
  сообщению («Ветка отсюда»), переключение веток, старые ветки сохраняются.
- **Контекст**: полоска использованных/лимит токенов (зелёный < 60%,
  жёлтый 60–85%, красный > 85%), «приблизительно» когда лимит неизвестен.
- **Handoff**: «Сжать историю» просит модель сделать резюме и открывает
  новый чат с ним как системным промптом; старый чат остаётся в истории.
- **Вложения**: фото / видео / аудио-файлы, если модель их поддерживает
  (см. раздел «Вложения»).
- **Локализация** ru / en / uk (автоопределение + ручной выбор),
  все ошибки провайдеров переведены и маппятся в понятные сообщения.
- **Настройки**: тема (системная/светлая/тёмная, dynamic color на
  Android 12+), язык, temperature, max_tokens, таймаут, глобальный и
  по-чатовый системный промпт, отладочный лог ошибок (сырые ответы API).

## Установка

Каждый push **с изменениями кода** в `main` публикует **GitHub Release**
с тегом `rN` и ассетом `AnyChat-arm64-rN.apk` (push, где тронута только
документация, CI не запускает — фильтр `paths-ignore`):

1. Откройте страницу **Releases** репозитория → последний релиз `rN`.
2. Скачайте ассет `AnyChat-arm64-rN.apk`.
3. Установите на устройство (разрешите установку из неизвестных источников).

Альтернатива — артефакт самой сборки: вкладка **Actions** → последний
успешный прогон → **Artifacts** → `AnyChat-<короткий sha>`
(в ZIP лежит `app-release.apk`).

Требования: Android 7.0+ (minSdk 24), интернет или локальный Ollama.

> Подпись release-сборки — debug-keystore Flutter (в репозитории сознательно
> нет keystore/`.jks`). Для Play Store подпишите своим ключом.

## Настройка провайдера

1. **Гамбургер → Настройки → «Провайдер и ключ»** — выберите одного из
   21 провайдера.
2. В карточке провайдера введите **API-ключ** и нажмите **Сохранить ключ**.
   В UI показывается только маска вида `sk-...abcd`; сам ключ хранится в
   `flutter_secure_storage` (Keystore Android) и никогда не попадает в БД
   и лог.
3. (Опционально) укажите **Base URL override** — для селф-хостинга, прокси
   или Ollama (`http://10.0.2.2:11434/v1` для эмулятора, свой адрес — для
   устройства). Пустое поле = адрес по умолчанию.
4. Нажмите **Проверить ключ** — AnyChat сделает минимальный chat-пробу
   (та же модель и формат, что в чате, `max_tokens: 32`, таймаут 60 с)
   и покажет ✅/❌ вместе с локализованной причиной ошибки.
5. **Настройки → раздел «Модели»** — выберите модель из списка (поиск,
   цена за 1M токенов, размер контекста, бейджи мультимодальности) либо
   введите ID вручную (поле «Своя модель»).
6. Вкладка **Настройки → «Генерация»** — при желании: temperature,
   max_tokens, таймаут, глобальный системный промпт (у конкретного чата
   он переопределяется: drawer → меню чата → «Системный промпт»).

Готово: возвращайтесь в чат (гамбургер → нужный диалог или «Новый чат»)
и просто пишите. Название чата присваивается из первого сообщения.

## Вложения (мультимодальность)

Возможности ввода модели определяют, что можно прикрепить (скрепка в
композере выключена, если модель не принимает медиа вообще):

| Медиа  | Форматы файлов            | Лимит |
|--------|---------------------------|-------|
| Фото   | jpg, jpeg, png, webp, gif | 20 МБ на файл |
| Видео  | mp4, mov, webm            | 20 МБ на файл |
| Аудио  | mp3, wav                  | 20 МБ на файл |

- **Откуда берутся возможности модели**: каталог провайдера
  (`modalities.input` у Vercel, `architecture.input_modalities` у
  OpenRouter) плюс эвристика по ID (`gpt-4o`/`claude`/`gemini` → фото,
  `gemini` → ещё видео и аудио). Нет ни того, ни другого — модель
  считается текстовой.
- **Как отправляются**: OpenAI-совместимые — `image_url` / `input_audio` /
  `video_url` (data-URI), Anthropic — `image` (base64), Gemini —
  `inlineData`.
- Вложения хранятся base64 прямо в строке сообщения (schema v2, миграция
  добавляет колонку автоматически), копируются при ветвлении; превью фото
  кэшируется, чтобы стрим не декодировал картинку на каждый токен.
- Нет записи с микрофона и генерации изображений — только готовые файлы.

## Design decisions

Решения, принятые автономно (и почему):

1. **Версии зафиксированы.** CI использует стабильный Flutter **3.47.8**
   (Dart 3.13.7); в `pubspec.yaml` — актуальные совместимые версии пакетов
   (Riverpod 3.x + `riverpod_annotation` 4.x, drift 2.35, dio 5.11,
   `file_picker` 13).
2. **Без `flutter create`.** Каталог `android/` написан вручную по шаблону
   `flutter create` для 3.47 (Kotlin DSL, AGP 9.1.0, Kotlin 2.4.0,
   Gradle 9.3.1, флаги `android.newDsl=false` / `android.builtInKotlin=false`).
   Gradle-wrapper (`gradlew`, `gradle-wrapper.jar`) не коммитится — Flutter
   сам докачивает его из кеша SDK при сборке.
3. **Без бинарников.** Иконка приложения — векторный
   `drawable/ic_launcher.xml` вместо PNG-mipmaps; никаких keystore, `.env`
   и ключей в репозитории.
4. **Ключи и конфиг разделены.** API-ключи — только в
   `flutter_secure_storage`; drift хранит `providers_config` (Base URL),
   чаты, ветки и сообщения (включая base64-вложения).
5. **Доменные модели отделены от drift-строк.** `riverpod_generator` не
   может разрешить типы, сгенерированные в `db.g.dart` (это `part`-файл):
   генерация падала с `InvalidTypeException`. Поэтому `Chat/Message/Branch`
   — обычные неизменяемые классы в `features/chat/domain/models.dart`,
   репозитории маппят строки через `fromRow`. Порядок кодогенерации в CI
   дополнительно подстрахован: сначала `db.g.dart` по build-фильтру,
   затем полный `build_runner`.
6. **`drift_flutter` вместо `sqlite3_flutter_libs`.** Так рекомендует
   документация drift: `driftDatabase(name:)` сам настраивает путь и
   нативные библиотеки.
7. **Собственный SSE-парсер** (`sse_parser.dart`) вместо `flutter_client_sse`:
   ~100 строк, покрыт тестами на разрезанные чанки, не тянет зависимости.
8. **Эвристика токенов.** Латиница /4, кириллица /2, прочие символы —
   1/символ, +4 на сообщение. Лимит контекста берётся из метаданных модели,
   иначе 128k с пометкой «приблизительно».
9. **Riverpod наполовину вручную.** `@riverpod` (codegen) — для нотифаеров
   и стрим-провайдеров; простые синглтоны (БД, репозитории, key-store) —
   обычные `Provider`, чтобы не плодить генерацию без нужды.
10. **Ошибки.** Один `ApiErrorType` на три wire-формата, локализация через
    ARB (en/ru/uk), сырые тела ответов — только в кольцевом debug-логе
    (последние 50 записей, экран «Отладочный лог ошибок» в настройках).
    Отображается локализованная причина, а не сырой JSON.
11. **Ветвление через копирование.** Fork ветки копирует её сообщения
    (транзакция drift) — проще и надёжнее переиспользования `parentId`;
    чаты в v1 небольшие.
12. **Проверка ключа — минимальный chat-проба** (модель и формат как в чате,
    `max_tokens: 32`, таймаут 60 с), а не запрос `/models`: у Vercel AI
    Gateway каталог моделей публичный (отвечает и без ключа), поэтому
    список ничего не доказывал бы о валидности ключа. При провале под
    кнопкой показывается локализованная причина (401 / таймаут /
    недоступная модель), сырой ответ уходит в отладочный лог.
13. **Vercel AI Gateway** добавлен как OpenAI-совместимый провайдер
    (`https://ai-gateway.vercel.sh/v1`): базовый URL и публичность
    `GET /models` проверены запросами к живому API, цены из каталога
    (`pricing.input/output`) парсятся наравне с OpenRouter
    (`prompt/completion`).
14. **Навигация и визуал в стиле ChatGPT (в рамках Material 3).** Приложение
    открывается сразу в чате; вместо `AppBar` — круглые плавающие кнопки
    (гамбургер-глиф из `CustomPainter` слева, «новый чат» справа), на
    пустом экране — заголовок «С чего начнем?» и композер, создающий первый
    чат при отправке. Композер вынесен в переиспользуемый `ChatComposer`
    (одна капсула: «+» слева, поле, круглая кнопка отправки справа).
    `Drawer`: заголовок AnyChat, список чатов с их меню, внизу pill
    «Новый чат» и шестерёнка «Настройки» (там же выбор модели).
    Отдельного экрана-списка чатов и нижней `NavigationBar` нет; Base URL
    показывается только как текст-помощь, без ссылки в поле.
    Переходы — обычный `Navigator`, go_router избыточен.
15. **`gen-l10n` c `nullable-getter: false`:** `AppLocalizations.of(context)`
    не-nullable, меньше `!` в UI-коде. Сгенерированные файлы не
    коммитятся — создаются в CI до `flutter analyze`.
16. **cleartext HTTP разрешён** (`android:usesCleartextTraffic="true"`) —
    нужен для локального Ollama по `http://`.
17. **Filled icon button.** В Flutter нет класса `FilledIconButton` —
    кнопка отправки это `IconButton.filled` (тот же Material 3 filled icon
    button), скругление поля — 28dp.
18. **JDK 21 в CI** — Gradle 9.3 / AGP 9.1 требуют 17+, 21 — стабильный
    LTS.
19. **Релизы автоматические.** Каждый успешный push в `main` создаёт
    GitHub Release с тегом `rN` (N = максимум существующих `rN` + 1),
    заголовком `AnyChat rN` и ассетом `AnyChat-arm64-rN.apk` — схема имени
    по требованию плюс расширение, чтобы Android считал файл APK.
    PR-прогоны релизов не создают; при гонке/повторном запуске workflow
    занимает следующий свободный номер тега.
20. **Мультимодальность по возможностям модели** — см. раздел «Вложения»:
    гейт скрепки по `ModelModality`, `file_picker` (SAF, без разрешений),
    base64 в строке сообщения и миграция схемы v1 → v2.

## Ограничения v1

- Только Android (iOS / web / desktop не поддерживаются).
- Нет рендеринга Markdown в ответах (обычный текст) и копирования блоками.
- Нет tool calling / функций и генерации изображений; вложений — только
  готовые файлы (без записи с микрофона), допустимые форматы зависят от
  модели и wire-формата провайдера; `video_url` для OpenAI-совместимых
  провайдеров — best-effort (не все провайдеры видео принимают).
- Нет экспорта/импорта чатов, поиска по истории и пагинации — чат целиком
  грузится в память.
- Лог ошибок хранится только в памяти процесса.
- Индикатор контекста — эвристика (без токенизатора), значения
  «приблизительно», когда лимит модели неизвестен.
- Fork ветки копирует сообщения — на экстремально длинных историях это
  может быть заметной задержкой.
- Список чатов в drawer отсортирован по дате создания (последние сверху),
  а не по последней активности.
- Иконка приложения упрощённая (вектор), release-сборка подписана
  debug-ключом.
- Для Xiaomi MiMo базовый URL помечен TODO и требует подтверждения.
- Локализация UI: en / ru / uk; названия провайдеров и моделей не
  переводятся.

## Разработка

**Политика CI:** `flutter analyze` — **0 issues** (любые error / warning /
info валят прогон), `flutter test` — зелёный, `flutter build apk
--release` — собирается, артефакт `AnyChat-<sha>` + релиз `rN`.

Push, затрагивающий только `**/*.md`, `LICENSE` или `.gitignore`, workflow
не запускает вовсе (`paths-ignore`) — правка README не пересобирает APK.

Этапы workflow (`.github/workflows/build.yml`):

```bash
flutter pub get
flutter gen-l10n
dart run build_runner build --build-filter=lib/core/storage/db.g.dart  # bootstrap
dart run build_runner build                                           # полная генерация
flutter analyze
flutter test
flutter build apk --release
# + загрузка ассета и публикация GitHub Release rN
```

Первый шаг `build_runner` нужен из-за `part 'db.g.dart'`: пока файла нет,
`riverpod_generator` не видит сгенерированные row-типы.

Локально (нужен Flutter SDK) команда для итераций:

```bash
flutter pub get
flutter gen-l10n
dart run build_runner build
flutter analyze
flutter test
```

**Тесты** (`flutter test`, только логика — без UI):

- `api_error_test` — маппинг ошибок всех классов для openai/anthropic/
  gemini (401/403/429/quota/контекст/модель/5xx, retry-after, DioException);
- `sse_parser_test` — парсинг SSE, чанки, разрезанные посреди слова,
  CRLF, комментарии, многократные события;
- `token_estimator_test` — эвристика латиница/кириллица/прочее;
- `adapters_test` — URL/заголовки/тела запросов трёх форматов, парсинг
  `/models` (цены OpenRouter и Vercel, контекст, модальности), разбор
  SSE-дельт, стрим через мок-dio, мультимодальные content-parts,
  `mergeTurns`;
- `provider_registry_test` — 21 провайдер, уникальность id, параметры
  Vercel, эвристика модальностей;
- `chat_models_test` — заголовки чатов, JSON-кодирование вложений.

Структура:

```
lib/
  main.dart, app.dart           # точка входа, темы, локализация, dynamic color
```
